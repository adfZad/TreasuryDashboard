Item

Detail

Purpose

Translate the approved business requirements and the current Treasury Excel model into implementable functional specifications for an IIS hosted web application with SQL Server as the system of record.

Primary business source

Business Requirement Document V1.docx.

Primary functional/data reference

Treasury report as on 15Aug2026.xlsx, including the executive dashboard, functional schedules, and individual bank/account worksheets.

Scope of this deliverable

Module list, role/permission model, approval workflow, Excel field mapping, validations, database entities/mappings, screen inventory, dashboard KPIs, audit requirements, and Phase 1 versus later-phase scope.

Design convention

Where the BRD or Excel does not define an exact rule, this FSD labels the item as Proposed or TBD rather than treating an assumption as an approved requirement.

3.1 Workflow Control Rules

Every approval/return action records Reporting Period, Business Unit where applicable, Approval Stage, User, Role, Action, Comment/Reason, Date and Time.

Maker-checker control prevents a user from approving their own submission where the same person performed the maker action.

A return requires a mandatory reason and records returned by, return timestamp, previous status and new status.

Relevant users receive an action notification after submission, return, review request, CFO request and publication.

CFO approval locks the financial version. CEO and Board views read only from the approved snapshot, not mutable operational tables.

Reopening requires an authorized user and mandatory reason, creates a new report version, and keeps the previously approved snapshot available for audit.

Derived design: BU workflow instances are tracked by Reporting Period + BU; Corporate Finance and CFO operate on the consolidated report version after required BU submissions reach the configured prerequisite stage or an authorized exception is approved.

3.2 Approval Gating

Gate

Rule

Outcome

Submission validation

No unresolved blocking validation errors for the submitting BU/module.

Block submission until corrected.

Reviewer validation

Reviewer can see errors, comments, attachments and exceptions in one workspace.

Reviewer may approve or return based on permissions.

Critical exceptions

Critical exceptions block final approval unless formally overridden by an authorized user.

Override reason and approver are audited.

CFO approval

All required consolidated data, management comments, version and exception status are presented.

Approval creates immutable snapshot and lock.

Publication

Only CFO-approved snapshot versions may be published.

CEO/Board can view only published/authorized snapshot.

6.1 Core Relationship Summary

ReportingPeriod → ReportVersion → TreasurySnapshot establishes period versioning and immutable approved history.

BusinessUnit / LegalEntity → BankAccount → BankBalance replaces the workbook pattern where each bank account has a separate worksheet and Funds Position links to B2 closing balance.

Bank / BusinessUnit / LegalEntity → WorkingCapitalFacility → FacilityUtilization normalizes sanction and utilization while supporting shared/parent limits.

BusinessUnit / LegalEntity → Loan → LoanRepayment and LoanMovementForecast replaces year/month columns with dated rows.

BusinessUnit → Investment → InvestmentValuation supports shares, metals and fixed deposits plus cost/market dashboard ratios.

BusinessUnit → CashFlowForecast by CashFlowCategory and bucket supports Group consolidation and later 13-week extension.

TreasurySubmission / ReportVersion → WorkflowInstance → WorkflowAction captures approval history. Comments and Exceptions can reference any module/record.

UploadBatch / UploadDetail / ValidationError preserves source-file traceability before validated rows are committed to production entities.

Each material data update should share a correlation/transaction identifier with the originating upload, web action or workflow action where applicable.

Approved snapshot/version history must allow auditors to reconstruct the exact CFO-approved position.

Retention period, archival policy, and whether login IP/device details are required are not specified in the BRD and remain TBD with IT/Internal Audit.

Appendix B. Key Excel Reconciliation Observations

Funds Position currently depends on one worksheet per bank account and commonly retrieves closing balance from cell B2. The target design replaces this with BankAccount and BankBalance rows.

Foreign-currency conversions in Funds Position use embedded rates such as USD 3.65, EUR/CHF 4.10, CAD 2.75 and AUD 2.35; another formula in Debt & Equity uses 3.645. Phase 1 must centralize these in approved FX Rate Master records.

The current workbook contains broken #REF! references in the executive dashboard and Debt & Equity calculations. Affected KPIs must not be accepted as migrated baseline values until the source is corrected and reconciled.

The dashboard contains multiple manually updated narrative areas. These should be implemented as structured comments tied to Reporting Period, module, BU/Group context, user, role and timestamp.

Working-capital dashboard commentary explicitly states that LC and Murabaha limits are sub-limits of total facility limits. The data model must support parent/shared limits and should not infer total sanction by simple addition.

The application should preserve Excel as an upload/export/reconciliation aid but SQL Server must become the authoritative source after validated import and workflow approval.
